Samuel · Design System

Style Guide

Dark-only. Flat neumorphic. Two brand hues. This page is rendered entirely with the project's own tokens — everything you see is the theme, demonstrated live. Sections 01–09 cover the token layer (globals.css); sections 10–14 document how the app's pages actually use it.

01

Design Philosophy

Samuel's UI rests on three principles:

Quiet darkness. A near-black canvas (#070709) with a slightly lifted card layer (#0f0f13). Depth comes from subtle elevation steps — never gradients or glows.

Two accents, used sparingly. Deep blue for primary actions and focus; orange only where the user must notice something. Everything else is neutral.

Flat neumorphism. Soft, low-opacity shadows (--nm-low/mid/high) suggest elevation without skeuomorphism. Inset shadows are disabled (--nm-inset: none). Borders do most of the structural work.

07

Interaction & Motion

  • Filled button hover — filter: brightness(1.15), no shadow change, no scale.
  • Outline hover — background shifts muted → border color, border takes primary. ~0.15–0.2s ease.
  • Opacity reveal — destructive/signout controls are invisible until their parent is hovered (opacity 0 → 1, 0.15–0.2s).
  • Dim-until-hover — long lists sit at opacity 0.72 → 1 on hover/focus-within.
  • Active step — pulsing primary border, pulse 1.4s infinite. Spinner rotates at 0.7s linear.
  • Focus ring — outline: 2px solid primary; outline-offset: 2px. Never removed.

08

Layout

Sidebar + main shell. Sidebar is fixed 330px at ≥1280px, sticky ~320px at ≥960px, stacked above main below that. Main content caps at 960px; generic container at 1024px with 1.5rem inline padding.

09

Do's & Don'ts

Do

  • Reuse existing tokens — every color, radius, shadow already exists in globals.css.
  • Stay flat — borders + flat shadows only.
  • Use accent orange sparingly — one highlight action per view.
  • Keep transitions short — 0.15–0.2s ease, nothing springy.
  • Demo the theme — when in doubt, mirror this guide's markup.

Don't

  • Never add gradients — depth comes from elevation steps, not blends.
  • Never introduce new hues — blue, orange, red, green. That's all.
  • No light mode — the theme is dark-only by design.
  • No inset shadows — --nm-inset stays none.
  • No decorative animation — motion exists to communicate state.

Page-Level Composition Patterns

Four page archetypes exist. All share the same header rhythm: an 800-weight h1 (2.5rem on dashboard/history, smaller elsewhere), a centered .text-muted subtitle, then a 3rem gap before content.

Login — app/page.tsx

Full-viewport centered column, max-width 480px. Logo tile (72px, primary bg, 12px radius) → title → muted blurb → login card → feature chips.

<main> flex center, min-height 100vh <div> max-width 480px, text-center [logo tile] [h1 "Samuel"] [.text-muted tagline] .nm-card padding 2rem ← sign-in card, one btn-primary btn-lg [chip row] gap .5rem, centered, wrapped

Session check first: while checking, the whole page renders as a single spinner-lg.

Dashboard / History — sidebar shell

Both use .page-shell + .sidebar-layout + .main-layout (layout classes from globals.css; see §08 for the responsive behavior). The sidebar ends with a pinned footer row separated by a top border: brand wordmark left, nav link right.

.page-shell aside.sidebar-layout ← Section cards + margin-top:auto footer .nm-card "GitHub Repositories" (+ username-tag in header) .nm-card "OpenRouter API Key" [footer row] border-top · Samuel ⇄ History/Dashboard link div.main-layout ← max-width 960px, centered, align-items:center h1 800 weight, centered ← e.g. "Samuel: Your Resume Tailor" p.text-muted centered ← 3rem bottom margin .dashboard-grid ← 1fr 1fr ≥768px, gap 2rem Section "Job Description" | Section "Resume (PDF)" + generate CTA

History mirrors this exactly with "Workspace Status" in the sidebar and a single-column list (max-width 720px) of clickable .nm-card rows in main.

Results — app/dashboard/results/[id]/page.tsx

No sidebar. A fixed right-hand timeline panel overlays the page while generating; main content is a centered 760px column that pads right by panel width and animates it away on collapse.

[fixed panel] width 220px, right edge, .color-card bg, border-left header: uppercase status label ("Generating"/"Complete"/"Error") + ✕ ProgressBar: 2px track (--color-border), primary fill, width % of done steps vertical timeline: 8px StepDot + 1px connector per step [connection error footer]: destructive text + full-width Retry btn main column, max-width 760px, padding-right adjusts when panel visible h1 state headline → .text-muted subline → content cards: {!done} nm-card "Working…" + spinner-sm {done} nm-card ATS score (2.25rem/800, color-coded) nm-card rewritten resume in <pre> action row: View History (.btn-sm) + ghost back button

11

Styling Approach (No Tailwind Runtime)

Despite Tailwind appearing in project docs, the frontend has no Tailwind dependency or config file. There is no tailwind.config.*; PostCSS exists only transitively via Next.js. Styling is two mechanisms only:

  • Custom classes from globals.css — .btn .btn-* .input .textarea .select .chip .step-item .step-icon .spinner .text-muted .text-xs .text-sm .font-mono .nm-card .nm-card-sm .nm-inset, plus layout classes (.page-shell .sidebar-layout .main-layout .dashboard-grid .container .custom-scrollbar .markdown-body .username-container). These are the component vocabulary — always prefer them.
  • Inline style={} props — used for everything page-specific: layout tweaks, gaps, font sizes, hover handlers (onMouseEnter border/background swaps). One-off values reference tokens via var(--color-*), never raw hex.

Convention: if a pattern repeats across pages, it lives (or should be treated as living) in globals.css. Inline styles are for positioning and micro-adjustments around those classes — not for re-specifying colors, radii, or shadows.

12

State & Feedback Patterns

As implemented across pages. Status colors are strict: pending = muted-fg/border, running = primary, success = #1a9e6e (literal green), error = destructive.

Async buttons disabled + spinner-sm inside replaces icon/text: Syncing... · Redirecting… · Starting generation.... Disabled opacity is 0.4 (globals).
Route-level loading Whole viewport centers a spinner-lg (login check, dashboard auth gate, history fetch). Optionally with "Loading…" beneath.
SSE step timeline Two renderings exist: card-style .step-item/.step-icon (pending ✓/number/! states) and the results-page dot timeline (§10). Both map to the same four statuses driven by step-start / step-done / step-error / done events.
Flash messages Dashboard-only inline banner: .nm-card-styled box, text colored by type (info = muted-fg, success = #1a9e6e, error = destructive). No toasts anywhere.
Status chips History rows show generation status as a recolored .chip (transparent bg, status-colored text), plus a plain "ATS n/100" chip when a report exists.
Destructive affordances Kept nearly invisible until needed: repo remove × appears on row hover, turns destructive on its own hover; Sign out slides in next to the username pill on hover (§07 reveal patterns).
Empty state History with zero generations: centered .nm-card, large muted stroke-icon (envelope SVG), heading, muted copy, one accent CTA ("Start generating").
Connection loss Results panel shows destructive "Connection lost." above a full-width default .btn Retry that resets steps and restarts the EventSource.

13

Iconography & Content Conventions

  • Inline SVG only. No icon library or emoji icons. Icons are hand-inlined 24-viewbox SVGs (GitHub mark, document logo, star, envelope) sized 10–40px, colored via fill/stroke="currentColor" or explicit token vars.
  • Text glyphs for controls. Close/remove is ✕ or ×; step done is ✓; external links append ↗; back navigation prefixes ←.
  • Star counts use a literal ★ character at ~0.7rem in muted-fg, never an SVG star in list rows.
  • Labels. Section/card labels are small caps: 0.65–0.72rem, weight 600–700, uppercase, letter-spacing 0.05–0.08em, muted-fg.
  • Truncation. Long strings (repo names, JD snippets, filenames) use ellipsis or line-clamp rather than wrapping.
  • Dates/times. Rendered via toLocaleDateString/toLocaleString, no custom formatting.
  • Language colors. The one sanctioned exception to "no new hues": GitHub's standard per-language hexes (LANG_COLORS in dashboard page.tsx) power 4px language bars and 6–8px dots. Do not extend this exception to anything else.
  • Markdown rendering. READMEs render through ReactMarkdown into .markdown-body (globals.css owns all its typography). Rewritten resumes display as plain pre-wrapped text instead.
